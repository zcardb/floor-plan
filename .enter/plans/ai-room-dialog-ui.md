## Context

用户认为截图中的「AI 布局 · 南阳台」弹窗过宽，已确认调整整个弹窗的宽度、输入区、信息层级和操作布局；强调只是 UI 调整。仅改房间 AI 布局弹窗，不扩展到 AI 创建户型或其他弹窗，不改数据库、AI 请求、模型默认值、方案数量默认值或生成/应用逻辑。

## 设计评审与依据

目标：让用户更容易阅读房间信息、描述需求并找到生成操作。不假设特定用户画像，不承诺转化率提升。依据已读取的 Growth.Design 心理学社区框架；不是官方认证，原则不规定固定弹窗宽度。

### 已做得好的地方
- 房间名称与尺寸自动带出，减少重复输入（Cognitive Load）。
- 家具与模型选择按需展开，不铺满选项（Progressive Disclosure / Hick’s Law）。
- 先预览、再应用且可撤销，已有明确的安全边界；继续保留。

### 主要问题与优先级
| 优先级 | 位置与根因 | 原则 | 推荐调整 |
| --- | --- | --- | --- |
| P1 | `src/index.css:3947` 的 `.ai-dialog` 共用 720px 宽度，截图显示单列内容横向空白大、阅读路径分散 | Visual Hierarchy / Cognitive Load | 房间弹窗独立限定 560px，不修改共享宽度 |

### Growth Design 诊断摘要
- Psych：现有自动填写与预览机制是加分项；需消除横向扫描、长提示及不明确箭头造成的认知消耗。不新增假进度或虚构处理步骤。
- B.I.A.S.：Block 的视觉层级需改；Interpret 的任务表达基本清楚但过长；Act 的主按钮辨识需改；Store 保留现有真实方案反馈，应用后的完整反馈不在本次评审范围。
- C.L.E.A.R. 启发式评分（截图和代码评估，并非用户测试）：文案 3/5、布局 2/5、强调 2/5、可访问性 3/5、反馈 4/5，共 14/25。颜色对比、键盘与触控仍需执行后验证。
- Web App 规则：降低边框噪声、保留真实状态；移动端适用大触控目标。本次保持现有 Dialog 交互，不为纯 UI 调整新增 Drawer 机制。
- 行为修复：保留已有默认模型和数量（Default Effect），降低旁支选择的视觉权重；不隐藏关键设置。
- 暗黑模式：截图未见明显诱导；不新增假倒计时、虚构推荐或默认修改参数，不隐藏「先预览、确认后应用、可撤销」语义。

## 推荐 UI

整体沿用项目暖色、克制的编辑器视觉，不换字体、不加插图或装饰性动效。

1. **尺寸与节奏**：房间弹窗输入态与结果态统一最大宽度 560px，实际宽度不超过视口减 24px；桌面内边距 24px，窄屏 16px；主要分组间距 16px。最大高度限制在视口内，内容可滚动。
2. **顶部**：保留「AI 布局 · 房间名」，标题与说明左对齐，给关闭按钮预留空间；说明改为「结合整套户型生成家具布局，先预览再应用，可撤销。」
3. **房间信息**：常驻显示房间面积，长宽放在次级位置；家具清单标为「家具（可选）」，未指定时提示「未指定时由 AI 从家具库挑选」。已有家具数量、尺寸编辑、移除与新增入口保留。
4. **输入区**：增加常驻「布局需求」标签，示例移到独立次级提示，placeholder 简化为「描述家具位置、使用需求或喜欢的风格…」。默认输入区域约 72px，高度仍随内容增长，上限保留 200px；减弱多重阴影，保留细边框与清晰聚焦态。
5. **底栏**：保留参考图入口、模型/小助手、方案数量；为房间场景启用 AiComposer 的可选呈现变体，生成按钮显示箭头及「生成方案」。模型与数量使用次级视觉，长名称省略但可完整识别。窄屏选项与主操作分两行，不挤压或横向溢出。
6. **结果态**：沿用 AiResults 与 PlanThumbnail；桌面方案网格最多两列，窄屏单列；进度与附加信息可换行，主次按钮清晰。「应用」文案改为「应用方案」。不改默认选中、重试、重新生成、后台生成与返回修改行为。

- `src/features/interior/components/AiComposer.tsx`：新增可选房间呈现变体，默认变体保持原样；保留 `reason`、`send`、textarea 自动高度与键盘/图片事件。
