# 墙段承重标记融入现有编辑器

## Context
现有 Demo 已预设承重墙、外围墙、隔墙和矮墙，但用户不能在界面中标记墙段的承重属性。本次把“选中整段墙 → 标记为承重墙”融入现有浮动工具条和右侧属性面板，不新增独立管理页面。

承重标记仅用于设计示意，不能代替建筑结构图或专业鉴定；不能根据墙厚、颜色自动判断承重。

## 推荐范围与交互
- 已完成阶段针对点击选中的完整墙段；现在新增下面的“墙段分割与局部承重标记”方案，取代原先不做分割的范围约束。批量标记、矮墙高度编辑和完整三态结构属性系统仍不纳入。
- 在墙体浮动工具条增加“承重”属性入口；右侧“墙体属性”提供同一控件，两处共用组件和模型操作。
- 普通墙显示“未标记承重”，操作为“标记为承重墙”；不要把未标记宣称为已鉴定非承重。
- 用户标记的墙显示“承重墙 · 用户标记”，可通过确认操作取消；确认提示取消标记不代表现实中可拆除。支持撤销、重做。
- 原有 `kind: bearing` 墙显示“原始承重墙 · 已锁定”，不提供解除入口；Demo 原始尺寸保护保持不变。
- 未拆除的内部墙、外围墙、矮墙均可增加承重标记，不改变原类型。已标记拆除的墙禁用操作，提示先撤销拆除；不自动恢复或删除任何对象。
- 显示沿用现有深色墙和“承重墙高亮”图层，增加明确文字状态；高亮图层只影响显示，不影响保护规则。矮墙属性名修正为“矮墙”。

## 数据与复用
保留 `Wall.kind` 和方案 `version: 2`，增加可选 `loadBearing?: boolean`。有效承重状态为原有 `kind === 'bearing'` 或 `loadBearing === true`；旧项目没有字段时行为不变。这样外围墙仍是外围墙，隔墙仍参与房间划分，矮墙仍保留现有高度。

新建纯模型模块 `src/features/interior/model/wallPolicy.ts`，统一有效承重判断、可编辑/可拆除/可标记策略及标记操作；UI、模型编辑和画布不得各自拼装不同规则。

复用：
- `useDesign.change/commit/undo/redo`：一次标记对应一次历史提交，并取消未提交的尺寸预览。
- 现有 `Popover`、`Button`、确认弹窗、语义颜色 token 和 `SelectionEditor` 锚点布局。
- `editSelection`、`createSizeTransaction`、`dimensionEditPolicy/editDimensionWalls`：沿用现有尺寸事务和连墙检查。
- `rebuildRooms`：标记本身不改变几何、不重新生成房间；后续合法结构操作仍按原流程划分。
- `validateDesign` 和现有项目 JSON 保存/导入链：字段随方案保存，无数据库迁移、无新增请求，不改生成的客户端或类型文件。

# 新增方案：墙段分割与局部承重标记

## Context
用户需要只把转角附近的一小段墙标记承重，而不是标记整面长墙。新增的是图纸对象分段，不是物理切割、挖除或开槽；分段不能改变建筑几何或自动判定承重。

## 推荐交互
1. 选中墙，在现有浮动工具条或右侧“墙体属性”点击“分割墙段”，打开同一个对话框，不增加顶部常驻工具。
2. 选择“单点分割”或“两点分割”。单点适合端部：例如从墙的起点量 0.30 m，得到 0.30 m 短段和剩余墙；两点适合中部：例如 0.30–0.80 m，得到三段。
3. 以米输入沿墙中心线、从起点 A 量取的距离；示意图标明 A/B、原墙长度、分割点和结果段长度，不依赖画布左右推断方向。支持选择应用后选中哪一段。
4. “应用分割”只提交分段，并选中指定子段；然后复用已有“标记为承重墙”。分割与标记各是一条撤销记录，不自动把其余墙鉴定为非承重。
5. 转角由两条墙组成；本期分别选择两侧分割，不自动把整个转角合成一个对象。不加入画布点选切刀、批量分割或合并墙段。

## 范围与保护
- Demo 和空白项目都可分割未拆除的墙，包括外围墙、隔墙、矮墙、用户标记承重墙和原始承重墙：分段只改变对象边界，不改变物理轮廓。
- 每个子段继承原 `kind`、承重标记、墙厚和颜色。原始 `kind: bearing` 分割后所有子段仍是原始承重墙，不允许通过分割解除锁定；不能把原始整段承重墙的其他部分自动变成普通墙。
- 普通长墙分割后只给需要的子段添加承重标记。若原墙是用户整段标记承重，子段全部继承标记；取消某段标记仍须既有确认，不自动取消。
- 采用每段中心线至少 0.05 m 的下限，与现有方案校验一致；墙段普通尺寸编辑继续沿用现有更严格下限。输入精度沿用当前米制工具，内部保持毫米浮点精度，不把旧墙几何四舍五入。
- 分割点落在门窗洞口内部时拒绝并提示调整位置，不拆分门窗、不移动洞口。分割点恰在洞口边界允许，用统一容差明确归属；门窗完整迁移到所属子段。
- 未拆除墙可分割；已拆墙禁用，先撤销拆除。超过方案 2000 段上限、非有限数、零长度、乱序或重复分割点拒绝；错误不留下部分子段。

## 模型与连锁实现
- 新增 `model/wallSplit.ts`：纯函数返回新方案与选中子段 ID；原 ID 留给第一段，其余用 `uid()`。门窗 ID、世界坐标、尺寸、开向和其他字段保留，只重绑 `wallId` 并减去子段起始距离更新 `offset`。
- `rooms`、家具、费用配置、测量和材质保持原对象，不调用 `rebuildRooms`；已有房间不能因分割被重新命名或重置材质。另做测试验证以后重建仍得到相同房间几何。
- 复用 `length`、`nearestOnWall`、`connectedWallPoly`、`wallSectionPolygons`。特别处理转角短段：现有连接算法用子段长度限制斜接伸出量，短段分割可能改变原墙角轮廓。需让同线连续子段的原始外端连接计算使用有效连续墙带长度，而非短子段长度；新增分段点采用平接，不产生缝隙、尖角或重叠面积。2D、面积重建、3D 和导出须检查同一建筑轮廓。
- 外围墙需加可选、稳定的 `exteriorRootId`，仅分割外围墙使用，值为其原外围墙 ID（不依赖已经存在的父对象）。首次和重复分割都继承同一根标识；旧方案没有该字段保持兼容。
- 修改 `resizeBlank`：检测有分割外围墙且请求改变净宽/净深/墙厚时拒绝，并解释“已分割外围墙，当前不支持整体重设外围尺寸”；相同尺寸调用必须保留全部子段及字段，不能重建成四段而丢失局部标记和开口。该限制同样在模型执行，不只禁用 UI。
- 复用 `dimensionBinding` 的连续墙带分组，不因新对象边界改变净距数字；含任一承重子段的整组墙带不能被净距工具整体移动，沿用 `dimensionEditPolicy` 的固定侧策略，不能误伤局部承重。
- 分割时通过 `useDesign.change/commit` 一次提交，取消尺寸预览；分割对话框绑定打开时的方案快照，方案改变或原墙消失后拒绝过期提交。关闭/取消不提交，历史恢复旧 ID 与门窗关联。
- 方案保存复用现有 JSON、本机和云端链路，无数据库迁移、无新增依赖或后端请求。费用按原长度求和，分割本身不增减新建/拆除费用或门窗费用分摊。
