# Interior 编辑器 UI 规范

本目录（`src/features/interior`）下所有新增或修改的 UI 都按这份规范来做。数值统一取自 `src/index.css` 顶部的编辑器刻度变量，**不要另外写死数字**。

## 1. 刻度变量（`src/index.css` `:root`）

| 用途 | 变量 | 值 |
|---|---|---|
| 标题 | `--fs-title` | 13px |
| 分组 / 控件文字 | `--fs-group` / `--fs-control` | 12px |
| 标签 / 辅助信息 | `--fs-label` / `--fs-meta` | 11px |
| 输入框 | `--fs-input` | 12px（触屏设备 16px，防止 iOS 自动放大） |
| 控件高度 | `--ctl-lg` / `--ctl-md` / `--ctl-sm` | 36 / 32 / 28px |
| 圆角 | `--ctl-radius` / `--ctl-radius-in` | 8 / 6px |

- 字号只允许 **11 / 12 / 13** 三档，不要出现 10px、14px 等其它字号。
- 颜色只能用语义 token（`hsl(var(--foreground))`、`--muted-foreground`、`--accent` 等），不要用 `text-white` 这类写死的颜色。

## 2. 选中对象浮动工具条（`.visual-selection-editor`）

统一规格：**11px、常规字重、按钮最小高度 `--ctl-md`（移动端 ≤600px 为 34px）、gap 5px、padding 0 8px、圆角 `--ctl-radius-in`**。

| 元素 | 图标尺寸 |
|---|---|
| 功能图标（尺寸、材质、开向、旋转、删除、详细属性等） | `size={15}` |
| 下拉箭头 `ChevronDown` | `size={12}` |

新增入口时：
- **用原生 `<button type="button">`**，并加上 `aria-label`。它会自动继承 `.visual-selection-editor > button` 和 `.editor-tooltip-trigger > button` 的统一样式。
- 需要弹层时用 `<PopoverTrigger asChild><button …/></PopoverTrigger>`，写法参考 `SelectionEditor.tsx` 里的「材质」和「开向」。
- 需要提示时用 `EditorTooltip` 包一层。

## 3. 不要在工具条 / 面板里直接用 shadcn `<Button>`

shadcn `Button` 的基础类会带上 `text-sm font-medium`（14px、500 字重）、`h-9`（36px）和 `[&_svg]:size-4`（图标强制 16px）。这些都**不会**被工具条的 CSS 覆盖，结果就是按钮比旁边的入口更大、更粗（之前「开向」就是这个问题）。

如果确实需要复用一个基于 `Button` 的组件（比如 `WallOptionsMenu`），必须在 `index.css` 中用**不在 `@layer` 里**的规则把这几项改回来：
```css
.xxx-trigger svg { width: 12px; height: 12px; }
.visual-selection-editor .xxx-trigger { height: auto; min-height: var(--ctl-md); padding: 0 8px; font-size: inherit; }
```
同时把它加进移动端 `min-height: 34px` 的规则里。

## 4. CSS 放置规则

- 编辑器控件样式写在 `index.css` 中 `@layer` **之外**，否则会被 Tailwind utilities 覆盖。
- 选择器挂在对应的语义 class 上（例如 `.visual-cost-trigger`），不要在组件里写行内样式或一次性的 Tailwind 尺寸类。
- 不要添加在 CSS 中没有定义的 class（例如以前的 `visual-door-direction`）。

## 5. 交互与心理学法则

来源：Growth.Design 的 106 条认知偏差与行为原则（<https://growth.design/psychology>）与其案例研究。这一段不是参考读物，而是**评审标准**：新增或修改 UI 时按下表逐条对照，写不清对应哪条法则的交互就不做。

写法约定：每条只写「为什么」和「在这个编辑器里具体怎么做」，不写空话。

| 法则 | 为什么重要 | 在本编辑器里怎么做 |
|---|---|---|
| **Hick's Law**（选项越多，决定越慢） | 工具条与面板天然选项密集，一次展示全部会让人卡住 | 常用操作直接露出，低频操作收进「更多」菜单；下拉里的选项按使用频率排序，不按字母排 |
| **Progressive Disclosure**（复杂功能按需展开） | 一次给全量参数会把新手劝退 | 面板先给最常用的一层（尺寸、材质），次级参数放进折叠区或弹出层 |
| **Default Bias**（多数人接受默认值） | 默认值往往就是最终值，选错默认等于持续添麻烦 | 默认值取「对多数人最合理的那个」而不是「成本最低的那个」：新建项目默认 9 × 10 m、家具清单默认带出房间现有家具、开向默认朝室内 |
| **Recognition over recall**（认出来比想起来容易） | 用户记不住家具名、材质名、房间名的准确写法 | 能用列表 / 选择器就不要用自由输入；家具、材质、房间一律给出可视选项与搜索框 |
| **Recognition + Chunking**（分组更易记） | 几十项平铺无法扫读 | 长列表按分类分组（家具按房间分类、材质按硬装 / 软装分类），每组一个标题 |
| **Feedback Loop**（没有反馈就会怀疑没生效） | 编辑器的每个操作都改数据，静默失败代价高 | 每个可点操作都要有结果反馈：成功 toast、失败原因、进行中的 loading；禁止「点了没反应」 |
| **Fitts's Law**（目标越大越近越快） | 触屏上小按钮点不中 | 主操作按钮不小于 `--ctl-md`，移动端可点区域不小于 34px；危险操作与主操作保持距离，避免误触 |
| **Von Restorff / Visual Hierarchy**（突出的才被看见） | 一屏里全都是同权重元素时，用户找不到重点 | 一屏只突出一个主操作；选中态、错误态用 `--primary` / `--destructive` 明确区分，不用微弱色差 |
| **Goal Gradient + Zeigarnik**（没完成的事会惦记） | 多步流程中断后用户容易忘 | 多步流程显示进度（第 N / M 步）；耗时任务允许中断并在原入口标记「已完成但未查看」，而不是静默丢弃 |
| **Peak-End Rule**（体验好坏由高峰和结尾决定） | 结尾糟糕会抹掉前面的顺利 | 流程结束给明确、可确认的收尾：创建成功后的落地提示、应用后的高亮、可撤销提示 |
| **Labor Illusion / Chronoception**（看到过程更认可结果，动效让等待更短） | 生成 / 计算类操作等待期间如果只有静止画面，会显得卡死且结果显得廉价 | 展示**真实**过程（当前步骤、已完成 / 总数），并让先完成的部分先出现；等待期间给动效或骨架屏 |
| **Provide Exit Points**（随时能停下来） | 被卡住的用户不会回来 | 每个弹窗 / 流程都有取消与返回，且返回后保留已填内容；长任务可取消；破坏性操作必须先确认 |
| **Spark Effect**（感知成本低才愿意开始） | 首次使用面临空白画布 | 空状态给出可直接点击的起点（模板、示例户型），而不是只写一句「暂无数据」 |

## 6. 伦理边界（不要越线）

助推（nudge）与操纵的区别只有一条：**用户是否还能轻松选别的**。以下在本项目里一律禁止：

- **禁止虚假进度**：进度条、阶段文案、耗时只能反映真实发生的步骤。不得为了「显得在努力」而故意延迟或编造阶段（Labor Illusion 的暗黑用法）。
- **禁止虚假稀缺与紧迫**：不写「仅剩 N 个」「限时」除非确有其事。
- **禁止默认值伤害用户**：默认选项不得为了留存 / 计费而违背用户利益。
- **禁止耻辱按钮**：拒绝 / 取消的文案就写「取消」「暂不」，不写「我更喜欢花钱」这类羞辱性选项。
- **永远保留退出路径**：取消、关闭、撤销必须一直可用且好找。

## 7. 自查清单（每次改动 UI 后）

- [ ] 字号只有 11 / 12 / 13，并且通过变量引用
- [ ] 工具条按钮的高度、字号、字重、图标尺寸和相邻按钮一致
- [ ] 没有在工具条或面板里直接使用 shadcn `Button`；如果复用了，已按第 3 节覆盖样式
- [ ] 移动端（390 宽）下按钮高度为 34px，工具条可以换行
- [ ] 一屏只有一个主操作，低频选项已收进「更多」或下拉
- [ ] 每个可点操作都有成功 / 失败 / 进行中的反馈，没有静默失败
- [ ] 耗时操作显示真实步骤与已完成数量，先完成的结果先出现
- [ ] 每个弹窗和流程都能取消 / 返回，返回后已填内容还在
- [ ] 默认值对多数用户是合理的，而不是对产品最有利的
- [ ] 没有虚假进度、虚假稀缺、胁迫式文案或耻辱按钮
- [ ] `pnpm run lint`、`pnpm test`、`pnpm run build` 全部通过
