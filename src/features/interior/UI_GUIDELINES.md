# Interior 编辑器 UI 规范

本目录（`src/features/interior`）下所有新增或修改的 UI 都按这份规范来做。数值统一取自 `src/index.css` 顶部的编辑器刻度变量，**不要另外写死数字**。

## 1. 刻度变量（`src/index.css` `:root`）

| 用途 | 变量 | 值 |
|---|---|---|
| 标题 | `--fs-title` | 13px |
| 分组 / 控件文字 | `--fs-group` / `--fs-control` | 12px |
| 标签 / 辅助信息 | `--fs-label` / `--fs-meta` | 11px |
| 菜单项第二行说明、角标 | `--fs-hint` | 10px |
| 指标卡数值（面积、长度、金额） | `--fs-figure` | 18px |
| 输入框 | `--fs-input` | 12px（触屏设备 16px，防止 iOS 自动放大） |
| 控件高度 | `--ctl-lg` / `--ctl-md` / `--ctl-sm` | 36 / 32 / 28px |
| 圆角 | `--ctl-radius` / `--ctl-radius-in` | 8 / 6px |

- 字号只允许 **10 / 11 / 12 / 13** 四档，并且通过变量引用。10px（`--fs-hint`）只能用在菜单项第二行说明和角标上，正文、标签不用。不要出现 11.5px、14px 等其它字号。唯一例外是指标卡里的数值，用 `--fs-figure`（18px），文字一律不用。
- **新加的界面先找现有的同类组件，照它的刻度做。** 不要自己定一套更大的字号或间距。之前「新建项目」菜单、「墙 ▾」下拉都比系统大了一档，原因就是没有照抄 `.wall-options-item`。
- 颜色只能用语义 token（`hsl(var(--foreground))`、`--muted-foreground`、`--accent` 等），不要用 `text-white` 这类写死的颜色。

## 2. 选中对象浮动工具条（`.visual-selection-editor`）

统一规格：**11px、常规字重、按钮最小高度 `--ctl-md`（移动端 ≤600px 为 34px）、gap 5px、padding 0 8px、圆角 `--ctl-radius-in`**。

| 元素 | 图标尺寸 |
|---|---|
| 功能图标（尺寸、硬装、家具、开向、旋转、删除等） | `size={15}` |
| 下拉箭头 `ChevronDown` | `size={12}` |

新增入口时：
- **用原生 `<button type="button">`**，并加上 `aria-label`。它会自动继承 `.visual-selection-editor > button` 和 `.editor-tooltip-trigger > button` 的统一样式。
- 需要弹层时用 `<PopoverTrigger asChild><button …/></PopoverTrigger>`，写法参考 `SelectionEditor.tsx` 里的「材质」和「开向」。
- 需要提示时用 `EditorTooltip` 包一层。

## 3. 不要在工具条 / 面板里直接用 shadcn `<Button>`

shadcn `Button` 的基础类会带上 `text-sm font-medium`（14px、500 字重）、`h-9`（36px）和 `[&_svg]:size-4`（图标强制 16px）。这些都**不会**被工具条的 CSS 覆盖，结果就是按钮比旁边的入口更大、更粗（之前「开向」就是这个问题）。

如果确实需要复用一个基于 `Button` 的组件（比如 `WallOptionsMenu`），必须在 `index.css` 中用**不在 `@layer` 里**的规则把这几项改回来：
```css
.xxx-trigger svg { width: 12px; height: 12px; }
.visual-selection-editor .xxx-trigger { height: auto; min-height: var(--ctl-md); padding: 0 8px; font-size: inherit; }
```
同时把它加进移动端 `min-height: 34px` 的规则里。

## 4. CSS 放置规则

- 编辑器控件样式写在 `index.css` 中 `@layer` **之外**，否则会被 Tailwind utilities 覆盖。
- 选择器挂在对应的语义 class 上（例如 `.visual-cost-trigger`），不要在组件里写行内样式或一次性的 Tailwind 尺寸类。
- 不要添加在 CSS 中没有定义的 class（例如以前的 `visual-door-direction`）。

## 5. 下拉菜单、弹层与色块的刻度

所有菜单都以现有的墙体选项菜单（`.wall-options-menu` / `.wall-options-item`）为准，新菜单照抄这些数值，不另起一套。

### 5.1 菜单容器

| 项 | 值 |
|---|---|
| 宽度 | 两行菜单 240–260px（`max-width: calc(100vw - 24px)`）；单行菜单 ≥ 200px |
| 内边距 | 6px |
| 分组标题 | `--fs-hint`，500 字重，`--muted-foreground`，padding `8px 9px 5px` |
| 分隔线 | 上下 6px |

### 5.2 单行菜单项（导出、账号、项目列表、返回等）

min-height `--ctl-md`（32px）、gap 8px、padding `0 10px`、圆角 `--ctl-radius-in`、字号 13px（shadcn 菜单默认值）、图标 14px。

### 5.3 两行菜单项（图标 + 标题 + 一行说明）

用在需要说明用途的菜单里，比如墙体选项、房间删除、「墙 ▾」工具、「新建项目」及其二级菜单。

| 项 | 值 |
|---|---|
| 行 | min-height 48px，`align-items: flex-start`，gap 10px，padding 9px，圆角 `--ctl-radius-in` |
| 图标 | 16px 线性图标，`stroke-width: 1.75`，`margin-top: 2px`，**不放底色图标块** |
| 标题 | `--fs-group`（12px）/ 行高 17px / 500 字重 |
| 说明 | `--fs-hint`（10px）/ 行高 15px / `--muted-foreground`，单行 |
| 标题与说明间距 | 3px |

- 同一个菜单里如果夹着单行项（例如「从其他软件导入」「返回项目管理」），左右 padding 也用 9px、gap 10px、图标 16px，字号 `--fs-group`，保证图标列和文字列对齐。
- 主操作（例如项目下拉里的「新建项目」）只用浅主色底 `--primary / 0.06` 和主色图标区分，不加边框，不用实色图标块，字号与其它项相同。
- 项目下拉是一个 184px 的窄菜单（比 §5.1 单行菜单更窄，属例外），只有三项纯文字入口：「返回项目管理」→「新建项目 ▸」→「切换项目 ▸」，不放左侧图标，只保留右侧 14px 子菜单箭头，后两项悬停展开二级菜单。项目行只有名称、日期和当前勾选；重命名、删除只放在项目管理页。
- 子菜单箭头 14px，`--muted-foreground`，垂直居中。
- 删菜单结构时，必须同步处理 `index.css` 里对应的 `.xxx-menu` / `.xxx-option` 规则：要么删掉规则并确认没有组件还在引用，要么保留。**不要留下「组件还在渲染这个 class、CSS 已经被删」的状态**——它不会有任何编译或测试报错，只会让菜单悄悄退回 shadcn 默认的大图标单行样式（「新建项目」菜单就这样坏过一次）。`toolbarMenus.test.tsx` 里有针对 `.create-menu` / `.create-option` / `.ai-icon` 的 CSS 断言兜底。

### 5.4 弹层（Popover）

padding `--sp-x`（16px），圆角 10px，标题 `--fs-title` 600，标题下方 12px，正文 `--fs-meta`，标签 `--fs-label`。颜色弹层（`.color-picker-panel`）也按这套。

- 头部用 `.visual-popover-head`：左边是标题，右边用 `--fs-meta` 灰字写对象名（例如「房间尺寸 … 堂屋」）。
- 弹层里有多块内容时，用 `.visual-popover-section` 做分组小标题（`--fs-label`、500 字重、灰色），例如「各边长度」。
- 只读指标用指标卡：浅底（`--secondary / 0.6`）、圆角 `--ctl-radius`、内边距 10px。标签 `--fs-label` 灰字，数值 `--fs-figure`，单位 `--fs-hint`。第一张是主指标，用 `--accent` 底、主色数值。不要只写一行小字，看起来太单调。
- 带图下拉（`FurniturePicker`）每行：左侧 32px 浅底缩略图块（`--canvas / 0.55`），右侧名称（`--fs-group` 500）加一行说明（`--fs-hint` 灰字），行高 44px。工具条入口可加 `heading`（标题 + 数量）。
- 弹层宽度按内容定：只列名称和尺寸的下拉用 `compact`（240px）；带分组、徽标、单价的用默认宽度（340px）。

### 5.5 颜色色块

- 工具条和属性面板里的颜色触发器（`ColorPicker variant="swatch"`）是一个和图标按钮同尺寸的 32×32 透明按钮，里面放 18px 的**纯色圆点**。圆点没有边框，也没有描边。悬停和打开时跟其它工具条按钮一样，只是按钮底色变成 `--accent`；键盘聚焦时显示 2px 主色 outline。
- 不要把色块直接当按钮本身。工具条通用的 `> button` 规则会给它加上 min-height 32px 和 padding `0 8px`，结果被撑成竖长胶囊。
- 表单里的「色块 + HEX」触发器（`variant="field"`）高度 `--ctl-lg`，字号 `--fs-control`。

### 5.6 AI 标识

- 所有 AI 入口统一使用 `AiIcon`：一大一小两颗实心四角星，主色（`.ai-icon`）。适用范围包括 AI 布局、AI 创建、AI 调整 / 生成。不要再用 lucide 的 `Sparkles`、`Wand`、`Bot`（`Bot` 只表示「小助手」这个对象）。
- 尺寸跟随所在行的图标：工具条 15px，按钮 14px，两行菜单 16px。

### 5.7 Visual Editor 工具条顺序

- 从左到右依次是：拖动手柄 → 名称 → 该对象的主操作（例如房间的「AI 布局」）→ 尺寸 → 属性下拉（硬装、家具、款式、楼梯、开向、图层……）→ 金额 → 图标操作（旋转、复制、删除）→ 关闭。
- 不再放「详细属性」按钮：所有调整都在工具条里完成。
- 房间的金额按钮只有金钱图标和金额，没有下拉箭头。点击后直接展开右侧的本间成本面板，单价在面板里逐项改。家具、门窗、墙体的金额按钮仍然打开单价弹层。
- 按钮文案用名词，不写数字或「本间」这类前缀。数量这类辅助数字放在文案后面，用灰字（`.visual-trigger-count`），例如「家具 4」。
- 房间和家具的名称在工具条里直接改（`EditorNameInput`），平时看起来就是粗体文字。规则和属性面板一样：回车或失焦提交，Esc 放弃，空名称恢复原名。
- 右侧属性面板能做的操作，工具条里也要有。图层顺序这类操作，面板和工具条共用同一个组件（`LayerMenu`），不要各写一份。

### 5.8 管理端页面（项目管理 / 家具管理 / 小助手）

- **外壳统一**：侧栏 + 右侧面板只用 `CmsLayout` / `CmsSidebar`（`CmsLayout.tsx`），页面内容自动包在 `.cms-page` 里，铺满 `.cms-main` 的内边距（桌面 36px、≤700px 16px）。**页面组件不要再写 `max-width` 或自己的左右 padding**（家具管理曾居中 1160px，和其它页留白不一致）。
- **页头一行**：`CmsPageHeader` 左边标题 + 说明；右边同一行依次是 `search`（`CmsSearchField`，280px、36px 高）→ 刷新 / 同步状态 → 主操作（新建）。窄屏操作行换到标题下方，搜索框占满剩余宽度。
- **筛选另起一行**：页头下方 `.cms-filter-rows`，一组一行，统一用 `CmsFilterGroup`：左侧分类描述（15px 图标 + 名称 + `N 项`，88px 列宽），右侧 `CmsFilterBar` 胶囊。项目管理一行「来源」；家具管理两行「硬装」「软装」。行间只用间距，不加箱式面板和分隔线。
- **分类胶囊**：高 `--ctl-md`、padding `0 12px`、圆角 `--ctl-radius-in`、1px `--border` 描边、透明底、`--fs-group` 灰字；数量用 `--fs-label` 灰字跟在后面；激活态 `--accent` 底 + 主色描边 + 600 字重。超出宽度横向滚动并两端渐隐。
- **骨架屏同版式**：`ManagementLoading` 的 `projects` / `library` 变体逐行对齐真实页面——页头（标题、说明 + 搜索、按钮骨架）→ 筛选行（分类描述 + 胶囊骨架，行数与页面一致）→ 结果标题 → 卡片网格。改了页面版式，必须同步改骨架。

## 6. 画布光标

- 选择模式下画布保持系统默认箭头，不切成十字或加号。拖动空白处可以直接框选，但不需要用光标来提示。
- 墙体和分隔线绘制工具用十字光标；家具、墙、门窗等对象各自用 pointer 或 move。
- 只有按住空格或中键平移时才显示抓手（grab / grabbing）。

## 7. 交互与心理学法则

来源：Growth.Design 的 106 条认知偏差与行为原则（<https://growth.design/psychology>）与其案例研究。这一段不是参考读物，而是**评审标准**：新增或修改 UI 时按下表逐条对照，写不清对应哪条法则的交互就不做。

写法约定：每条只写「为什么」和「在这个编辑器里具体怎么做」，不写空话。

| 法则 | 为什么重要 | 在本编辑器里怎么做 |
|---|---|---|
| **Hick's Law**（选项越多，决定越慢） | 工具条与面板天然选项密集，一次展示全部会让人卡住 | 常用操作直接露出，低频操作收进「更多」菜单；下拉里的选项按使用频率排序，不按字母排 |
| **Progressive Disclosure**（复杂功能按需展开） | 一次给全量参数会把新手劝退 | 面板先给最常用的一层（尺寸、材质），次级参数放进折叠区或弹出层 |
| **Default Bias**（多数人接受默认值） | 默认值往往就是最终值，选错默认等于持续添麻烦 | 默认值取「对多数人最合理的那个」而不是「成本最低的那个」：新建项目默认 9 × 10 m、家具清单默认带出房间现有家具、开向默认朝室内 |
| **Recognition over recall**（认出来比想起来容易） | 用户记不住家具名、材质名、房间名的准确写法 | 能用列表 / 选择器就不要用自由输入；家具、材质、房间一律给出可视选项与搜索框 |
| **Recognition + Chunking**（分组更易记） | 几十项平铺无法扫读 | 长列表按分类分组（家具按房间分类、材质按硬装 / 软装分类），每组一个标题 |
| **Feedback Loop**（没有反馈就会怀疑没生效） | 编辑器的每个操作都改数据，静默失败代价高 | 每个可点操作都要有结果反馈：成功 toast、失败原因、进行中的 loading；禁止「点了没反应」 |
| **Fitts's Law**（目标越大越近越快） | 触屏上小按钮点不中 | 主操作按钮不小于 `--ctl-md`，移动端可点区域不小于 34px；危险操作与主操作保持距离，避免误触 |
| **Von Restorff / Visual Hierarchy**（突出的才被看见） | 一屏里全都是同权重元素时，用户找不到重点 | 一屏只突出一个主操作；选中态、错误态用 `--primary` / `--destructive` 明确区分，不用微弱色差 |
| **Goal Gradient + Zeigarnik**（没完成的事会惦记） | 多步流程中断后用户容易忘 | 多步流程显示进度（第 N / M 步）；耗时任务允许中断并在原入口标记「已完成但未查看」，而不是静默丢弃 |
| **Peak-End Rule**（体验好坏由高峰和结尾决定） | 结尾糟糕会抹掉前面的顺利 | 流程结束给明确、可确认的收尾：创建成功后的落地提示、应用后的高亮、可撤销提示 |
| **Labor Illusion / Chronoception**（看到过程更认可结果，动效让等待更短） | 生成 / 计算类操作等待期间如果只有静止画面，会显得卡死且结果显得廉价 | 展示**真实**过程（当前步骤、已完成 / 总数），并让先完成的部分先出现；等待期间给动效或骨架屏 |
| **Provide Exit Points**（随时能停下来） | 被卡住的用户不会回来 | 每个弹窗 / 流程都有取消与返回，且返回后保留已填内容；长任务可取消；破坏性操作必须先确认 |
| **Spark Effect**（感知成本低才愿意开始） | 首次使用面临空白画布 | 空状态给出可直接点击的起点（模板、示例户型），而不是只写一句「暂无数据」 |

## 8. 伦理边界（不要越线）

助推（nudge）与操纵的区别只有一条：**用户是否还能轻松选别的**。以下在本项目里一律禁止：

- **禁止虚假进度**：进度条、阶段文案、耗时只能反映真实发生的步骤。不得为了「显得在努力」而故意延迟或编造阶段（Labor Illusion 的暗黑用法）。
- **禁止虚假稀缺与紧迫**：不写「仅剩 N 个」「限时」除非确有其事。
- **禁止默认值伤害用户**：默认选项不得为了留存 / 计费而违背用户利益。
- **禁止耻辱按钮**：拒绝 / 取消的文案就写「取消」「暂不」，不写「我更喜欢花钱」这类羞辱性选项。
- **永远保留退出路径**：取消、关闭、撤销必须一直可用且好找。

- [ ] 新菜单照抄了第 5 节的刻度：两行项 48px 行高 / padding 9px / 16px 图标 / 标题 12px / 说明 10px
- [ ] 工具条按钮的高度、字号、字重、图标尺寸和相邻按钮一致
- [ ] 没有在工具条或面板里直接使用 shadcn `Button`；如果复用了，已按第 3 节覆盖样式
- [ ] 移动端（390 宽）下按钮高度为 34px，工具条可以换行
- [ ] 一屏只有一个主操作，低频选项已收进「更多」或下拉
- [ ] 每个可点操作都有成功 / 失败 / 进行中的反馈，没有静默失败
